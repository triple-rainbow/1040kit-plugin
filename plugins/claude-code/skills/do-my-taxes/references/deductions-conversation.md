# Finding deductions with the user

`deductions_find({ workspace })` returns `opportunities`, a list of items, each with `id`, `title`, `eligibility` (the test), `question` (what to ask), `docsNeeded`, `estimatedSavings` (whole dollars, or null), `status`, `citations`, `factPaths` (where to record the answer, with `<owner>` / `<id>` placeholders for you to fill in) and, for business expenses, `scheduleCCategory`. They come sorted by estimated savings.

**Record answers at the item's `factPaths`.** The table below explains what to ask for each; if it ever disagrees with `factPaths`, `factPaths` wins.

## How to walk the list

- `claimed`: already on the return. Mention it briefly ("your return already includes the QBI deduction") with its citation.
- `flag_only`: something 1040kit can't put on the return. Explain it (below) and let the user decide; never record it as a claim.
- `possible`: one at a time, in the order given:
  1. Say what it is in one plain sentence and that they **might** be eligible. If `estimatedSavings` is a number, you may say "up to $X, if you're eligible"; if it's null, say 1040kit can't estimate it.
  2. Read the `eligibility` test in plain words and ask the `question`. Mention the citation.
  3. If the answer is no or unsure, move on. Don't push.
  4. If yes and `docsNeeded` is not empty, ask them to have those documents and keep them with their tax records. If a document holds an amount, they can save it in the inbox and you run `docs_scan` and `docs_extract`; otherwise ask them for the amount from the document.
  5. Record the facts with `profile_set` (`source: 'user'`) at the paths below. Amounts are in cents: the user's $1,234.56 is `123456`.
  6. Call `calc_return` and tell them the new refund or amount owed, exactly as returned. Only now may you say the deduction is on their return.

Ask at most 5 questions per message. Group related ones (all the business-expense items together).

## Flag-only items

- `itemize_flag`: itemizing might give them a bigger deduction than the standard deduction. 1040kit can't itemize (Schedule A is planned for v1.1). Say so plainly and let them choose: continue with the standard deduction, or use other software or a tax professional to compare. If they want to itemize, record `outOfScope.wantsToItemize: true` and follow `out-of-scope.md`.

## What-ifs (`scenario_compare`)

Use it whenever the user asks "what if…". Example, SEP-IRA:

```
scenario_compare({ workspace, scenarios: [
  { name: 'SEP $3,000', patch: { adjustments: { sepContributions: { taxpayer: 300000 } } } },
  { name: 'SEP $6,000', patch: { adjustments: { sepContributions: { taxpayer: 600000 } } } }
] })
```

Quote each scenario's `delta.refundOrOwed` and `delta.totalTax` as returned. Pick the trial amounts from what the user says they can afford; don't compute a maximum contribution yourself. If they ask about limits, use the item's citation or `kb_search`. A scenario changes nothing on the return; record the real choice with `profile_set` afterwards.
